# Decision log

Record an owner, date, and rationale when resolving a decision. Suggestions in the outline are not approved Fund policy.

| Decision | Proposal or question | Status |
| --- | --- | --- |
| Learning boundary | Evidence preparation only; analyst owns interpretation and final updates | Blueprint principle; validate with Fund |
| Movement definition | Absolute difference of daily returns >= 4 percentage points versus SPX | Needs Fund approval |
| Observation mode | Intraday heads-up and official determination at close, or close only? | Open; pilot blocker |
| Market conventions | Data provider, SPX access, prior close adjustments, session calendar, timestamp tolerance | Open; pilot blocker |
| Pilot team | Team, holdings, owners, and access roles | Open; pilot blocker |
| Deadlines | Due-time calculation, timezone, holidays, reassignment and escalation | Open; pilot blocker |
| Notifications | Channel, recipients, reminder cadence, delivery failure owner | Open; pilot blocker |
| Technical stack | Runtime, database, auth, jobs, hosting, cost budget | Open |
| Source handling | Approved providers, storage rights, retention, research permissions | Open |
| Historicals integration | Existing interface, mapping format, model write/approval boundary | Deferred to phase 3 |
| Proficiency | Who authorizes greater automation and how competence is demonstrated | Deferred to phase 3 |
| Research approval | Who approves team positions and cross-team visibility | Resolve before cross-team rollout |
| Repository licensing | Private collaboration initially; no open-source license selected | Open |
